Свидетельства

 • ev-001 k8s_list_pods — namespace payments: подов 1, проблемных 1 (api-86d9b8c4bd-c964p=Error)
 • ev-002 k8s_describe — Pod api-86d9b8c4bd-c964p в namespace payments: контейнеры в состоянии CrashLoopBackOff
 • ev-003 k8s_logs — лог пода api-86d9b8c4bd-c964p предыдущего запуска: 3 строк; последняя: [api] FATAL: environment variable DB_PASSWORD is not set;
   cannot connect to database payments
 • ev-004 k8s_get_manifest — манифест Deployment api из namespace payments

Скилл: crashloop-diagnosis

Причина

В манифесте Deployment api (namespace payments) отсутствует переменная окружения DB_PASSWORD: заданы DB_HOST, DB_NAME и DB_USER (через secretKeyRef
payments-db/username), но нет DB_PASSWORD (ev-004). Контейнер при старте проверяет [ -z "${DB_PASSWORD:-}" ] и завершается с exit 1, что
подтверждается логом предыдущего запуска: "FATAL: environment variable DB_PASSWORD is not set" (ev-003) и статусом контейнера terminated/Error с
exit_code 1 (ev-001, ev-002). Это и вызывает CrashLoopBackOff. (уверенность: high; свидетельства: ev-004, ev-003, ev-001, ev-002)

 • альтернатива: Альтернативно: DB_PASSWORD мог задумываться для передачи через Secret payments-db (аналогично DB_USER через secretKeyRef), но
   соответствующий env-блок с ключом password в манифесте не описан — либо Secret не содержит ключ password. Проверить содержимое Secret без раскрытия
   значений (только наличие ключей) пока невозможно: таких свидетельств нет.

Исправление

Применить патч, добавляющий DB_PASSWORD через secretKeyRef на Secret payments-db (namespace payments), после подтверждения, что ключ password в этом
Secret существует. После применения перепроверить состояние пода и логи, чтобы убедиться в успешном старте контейнера.

Скилл: crashloop-diagnosis

Причина

В манифесте Deployment api (namespace payments) отсутствует переменная окружения DB_PASSWORD: контейнер при старте проверяет [ -z "${DB_PASSWORD:-}" ]
и завершается с exit 1, что и вызывает CrashLoopBackOff. (уверенность: high; свидетельства: ev-004, ev-005, ev-001, ev-002)

 • альтернатива: Secret payments-db в namespace payments повреждён или ключ password в нём отсутствует, из-за чего DB_PASSWORD не подставляется даже
   при корректной ссылке. Однако в манифесте Deployment api ссылки на DB_PASSWORD нет вовсе, поэтому эта гипотеза вторична и относится к возможному
   следующему шагу после добавления env.

Исправление

Применить strategic merge patch к Deployment api в namespace payments: добавить env DB_PASSWORD через valueFrom.secretKeyRef на существующий Secret
payments-db (ключ password), как у checkout. После применения перепроверить состояние пода и логи; если под всё ещё падает — проверить наличие ключа
password в Secret payments-db (сейчас это не подтверждено напрямую).
