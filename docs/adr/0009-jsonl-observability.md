# 0009. Наблюдаемость: JSONL-трейс и метрики из трейсов вместо Langfuse

**Статус:** Принято, дата 2026-10-10

## Контекст

N5 требует видеть каждый прогон, вызовы модели и инструментов, а N4 — стоимость.
CLI завершается примерно за 30 секунд, тогда как Prometheus скрейпит раз в 15 секунд.
Счётчики только в памяти процесса теряются при перезапуске и требуют pushgateway.
Полный Langfuse-стек слишком тяжёл для учебного ноутбука и demo-стенда.

## Решение

Источник истины — JSONL-файл на прогон `data/traces/<run_id>.jsonl`.
События включают `run_start`, `node`, `llm`, `format_retry`, `tool`, `memory_search`, `approval`, `run_end`.
В трейсе сохраняются уже замаскированные промпты и ответы, latency и cost.
Команда `k8s-agent trace <run_id>` показывает временную шкалу прогона.
`k8s-agent metrics serve` при каждом scrape агрегирует все JSONL-файлы.
Prometheus получает счётчики и гистограммы без pushgateway.
Длительность прогона исключает время ожидания человека на `approval`.
Алерты хранятся в `observability/alerts.yml` и проверяются `promtool test rules`.
Контракт метрик фиксирует labels для route, model, node, tool, status и decision.

## Последствия

Плюсы:
- трейс переживает перезапуск процесса и остаётся артефактом защиты;
- метрики воспроизводятся повторным скрейпом файлов;
- стек поднимается малым числом контейнеров;
- искусственное срабатывание алертов проверяется в CI.

Цена:
- нужно следить за ротацией и приватностью файлов трейсов;
- агрегатор читает файлы при каждом scrape и не является постоянной БД;
- нет готового Langfuse UI и встроенной разметки scores.

## Отвергнутые варианты

- **Langfuse self-hosted** — Postgres, ClickHouse, Redis и S3 избыточны для v1 ноутбука.
- **Счётчики в процессе** — короткий CLI завершится до стабильного scrape.
- **Pushgateway** — добавляет сервис и вторую точку истины.
