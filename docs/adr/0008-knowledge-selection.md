# 0008. Знания: скилл по triggers кодом, runbook по оглавлению

**Статус:** Принято, дата 2026-10-10

## Контекст

Знания проекта состоят из SOUL, IDENTITY, скиллов и runbook-файлов.
Плоское разбиение markdown теряет границы процедур и смешивает симптом с причиной.
Для защиты нужна объяснимость: можно показать, почему скилл или раздел был выбран.
Код уже содержит детерминированный выбор скилла и чтение разделов runbook.

## Решение

Скиллы лежат в `skills/*/SKILL.md` с YAML-фронтматтером и `triggers`.
`select_skill` выбирает скилл по числу совпадений, затем по длине триггеров.
Выбранное имя и тело добавляются в план и диагностический промпт.
Runbook сначала превращается в оглавление `файл › заголовок раздела`.
Модель выбирает номер раздела, после чего в контекст попадает только этот раздел.
Это структурный подход PageIndex, без векторного RAG по чанкам.
`SOUL.md` добавляется в системный промпт всех узлов.
`IDENTITY.md` добавляется оркестратору и классификатору.
Название скилла и ссылки на прошлые инциденты видны в отчёте.

## Последствия

Плюсы:
- выбор повторяем и объясним по trigger и заголовку;
- меньше лишнего контекста и ниже риск смешать процедуры;
- инструкции поведения отделены от фактов кластера;
- изменение знаний не требует перестройки индекса.

Цена:
- синоним без совпавшего trigger не подключит скилл;
- качество выбора раздела зависит от одной структурированной классификации;
- длинный раздел всё ещё может быть большим контекстом.

## Отвергнутые варианты

- **RAG по чанкам** — теряются иерархия runbook и временная связь фиксов.
- **Всегда загружать все markdown** — растут контекст и риск противоречивых указаний.
- **Выбор скилла самой моделью без кода** — нельзя надёжно объяснить trigger и маршрут.
