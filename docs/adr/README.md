# Архитектурные решения

| Номер | Решение | Почему |
|---|---|---|
| 0001 | LangGraph и собственный LLM-клиент | Один клиент измеряет ровно тот же HTTP-путь, что и агент. |
| 0002 | Два контура и две ServiceAccount | Read-only диагностика не получает права мутации. |
| 0003 | Allowlist патча и привязка к evidence | Код блокирует опасные поля, чужой объект и устаревший объект. |
| 0004 | Internal-сеть и tinyproxy allowlist | Egress ограничен парами «имя:порт» без хостовых iptables. |
| 0005 | `z-ai/glm-5.3`, reasoning low | М3 дал лучший итог и S1 26 секунд; flash ждёт М8. |
| 0006 | `json_schema` или `json_object` по схеме | Закрытые схемы строгие, открытый patch не зацикливается. |
| 0007 | SQLite + FTS5 | Память помещается в 512 МиБ без bge-m3 и внешних embeddings. |
| 0008 | Скиллы по triggers, runbook по оглавлению | Структурный выбор объясним и не теряет иерархию. |
| 0009 | JSONL-трейс, Prometheus из файлов | Нет pushgateway и тяжёлого Langfuse, трейс остаётся источником истины. |
| 0010 | Изолированные системные evals | Граф до approval проверяется безопасно, память кейса живёт в ОЗУ. |
