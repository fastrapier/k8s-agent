# 0001. LangGraph для графа и свой тонкий клиент LLM

**Статус:** Принято, дата 2026-10-10

## Контекст

Графу нужны явные состояния, циклы ревью, маршрутизация и пауза для человека.
Вызовы LLM должны иметь единый контракт, таймауты, повторы шлюза и учёт цены.
Сравнение моделей М3 имеет смысл только при том же HTTP-клиенте, который работает в агенте.
Готовые LangChain-модели добавили бы скрытые настройки и расхождение с evals.

## Решение

Оркестрация реализуется на LangGraph через `StateGraph` и узлы `classify`–`report`.
Маршрут между узлами задаётся кодом, а модель решает только внутри узла.
Пауза подтверждения выполняется `interrupt()` из `langgraph.types`.
В CLI граф компилируется с `SqliteSaver` для восстановления по `thread_id`.
LLM вызывается собственным `LLMClient` из `llm.py`.
Клиент отправляет OpenAI-совместимый `/chat/completions` через `urllib`.
Он задаёт `temperature`, `top_p`, `reasoning_effort`, таймаут 120 секунд и повторы 429/5xx.
Один клиент используется и графом, и `evals/model_selection.py`.

## Последствия

Плюсы:
- состояние, циклы и resume видны в коде графа;
- evals меряют реальный путь запроса, включая прокси и форматирование;
- нет скрытого адаптера LangChain и лишнего runtime;
- стоимость и задержка собираются в одном месте.

Цена:
- нужно самостоятельно поддерживать разбор JSON и обработку ошибок HTTP;
- API LangGraph и `SqliteSaver` остаются обязательной зависимостью;
- смена провайдера требует сохранить OpenAI-совместимый контракт.

## Отвергнутые варианты

- **LangChain-модели** — сравнительный harness и агент могли бы использовать разные клиенты.
- **CrewAI/AutoGen** — слабее контроль над состоянием, циклами и детерминированным роутингом.
- **Чистый Python без LangGraph** — пришлось бы заново реализовать checkpoint и interrupt.
