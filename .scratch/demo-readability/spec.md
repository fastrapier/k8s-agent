# Читаемый вывод демо и свежий токен агента

**Зачем.** Прогон `make demo` 2026-10-12 показал две проблемы.
1. Токены учёток агента выпускаются на 24 ч (`stand/lib.sh`), стенд поднимали 10.10 — к 12.10 все
   вызовы инструментов вернули Unauthorized, S1 и S5 ушли в «unresolved». `stand-status` ходит под
   админом и этого не видит. Перевыпустить токен можно было только через `make stand-up`, который
   ещё и тянет metrics-server с github.com (бывает недоступен).
2. Вывод прогона нельзя читать: нет границ инцидента, лог узлов графа, текст скилла, вопрос о патче
   и отчёт агента идут сплошным текстом; скилл (20 строк) вклинивается между `plan` и `diagnose`;
   длинный план переносится с нулевой колонки.

**Что делаем.**
- `make stand-tokens` — перевыпуск четырёх kubeconfig'ов учёток без похода в сеть; `up.sh` зовёт ту
  же функцию. Шаг 1 демо перевыпускает токен, `stand-status` проверяет, что токен диагноста
  принимается. Подсказка в ошибке 401 — `make stand-tokens`.
- `k8s-agent run`: рамка «Инцидент <id>» с жалобой → «ход расследования» (узел слева, текст с
  отступом, план по пунктам) → скилл в отдельной рамке → «нужно ваше решение» в жёлтой рамке →
  «Ответ агента» → «конец инцидента · трейс».
- `make demo`: у каждого шага заголовок и строка «смотреть: …».
- Найдено на прогоне: `break.sh s1` при уже сломанном S1 засчитывал restartCount уходящих подов
  старого Deployment, и шаг 1 показывал «ещё не дошёл, restartCount=0». Теперь ждём их удаления.

**Чего не трогаем.** Граф, промпты, текст отчёта, срок токена (24 ч — аргумент в DEFENSE.md).
Evals вызывают граф напрямую, CLI не используют — перепрогон evals не нужен.

**Почему не проще.** Продлить токен до недели — убрать аргумент «украденный файл завтра бесполезен».
Только `make stand-up` перед защитой — сутки спустя снова сломается, и сеть нужна.

**Как проверено.** `make check`; `make stand-tokens` + `stand-status` на живом стенде; полный
`make demo` с подтверждением патча; запись прогона в `docs/demo/make-demo.txt`.
