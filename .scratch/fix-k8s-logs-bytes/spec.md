# k8s_logs: лог как текст, а не repr байтов; текст кластера в CLI — без разметки

Статус: реализовано, PR на ревью. Найдено при проверке М2.1 на живом kind.

## Зачем

ТЗ F3 и сценарий S1: причина CrashLoopBackOff видна в логе предыдущего запуска —
`FATAL: environment variable DB_PASSWORD is not set`. Это главное свидетельство S1.
Живой прогон показал, что `k8s_logs` возвращал лог как `b'[api] starting…\n[api] FATAL…'`:
клиент `kubernetes` 36.0.3 отдаёт `read_namespaced_pod_log` в виде `str(bytes)`. Весь лог
превращался в одну строку с буквальными `\n` («1 строк»), обрезка и маскирование работали
по repr. На М4 модель получила бы именно это.

Второе, найдено тем же прогоном: CLI печатал summary и сырой вывод как разметку `rich`.
`[api]` в начале строки лога исчезал, а `[/api]` вызвал бы `MarkupError` и уронил команду.
Логи и события — недоверенные данные (ISOLATION T2), интерпретировать их нельзя.

## Что делаем

1. `k8s_logs`: `_preload_content=False` и явный `.decode("utf-8", errors="replace")`.
2. CLI: summary и error экранируются, сырой вывод печатается с `markup=False`.
3. Тесты: лог из байтов приходит строками; CLI печатает `[api]` и `[/api]` как есть.
   Оба теста падают на старом коде.
4. CI: на живом kind `k8s_logs --previous` для пода S1 приносит FATAL-строку.

## Почему не проще

- **Срезать `b'` и раскодировать `\n` из repr.** Ломается на кавычках, юникоде и экранированных
  символах внутри лога. Сырые байты и `decode` — штатный способ клиента.
- **Понизить версию клиента.** Версии прибиты ради N6, а поведение `str(bytes)` у клиента
  давнее; лечить надо там, где мы читаем ответ.
- **Отключить разметку в `Console` целиком.** Тогда пропадут цвета статусов, на которые
  смотрит человек. Экранируется только то, что пришло из кластера.

## Проверка

`make check` — 59 тестов; новые тесты на старом коде падают. Живой kind: `k8s_logs` и
`k8s_logs --previous` для пода api — 3 строки, последняя
`[api] FATAL: environment variable DB_PASSWORD is not set…`. CI зелёный.
